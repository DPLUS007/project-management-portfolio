# AI / LLM Evaluation Checklist

A lightweight delivery checklist for translating AI product requirements into observable, testable quality criteria.

## 1. Use case and requirements
- [ ] Define the user problem and intended outcome.
- [ ] Identify target users and representative scenarios.
- [ ] Document functional and non-functional requirements.
- [ ] Define assumptions, constraints and out-of-scope behavior.
- [ ] Agree measurable acceptance criteria.

## 2. Evaluation scenarios
- [ ] Create representative normal-use scenarios.
- [ ] Include edge cases and ambiguous inputs.
- [ ] Define expected characteristics of a successful response.
- [ ] Identify unacceptable failure modes.
- [ ] Maintain traceability between requirements and evaluation scenarios.

## 3. Quality review
| Evaluation Area | Criteria | Result | Evidence / Notes | Owner |
|---|---|---|---|---|
| Relevance | Output addresses the requested task |  |  |  |
| Accuracy | Verifiable claims meet agreed expectations |  |  |  |
| Completeness | Required elements are present |  |  |  |
| Consistency | Similar scenarios receive appropriately consistent treatment |  |  |  |
| Usability | Output is clear and useful to the intended user |  |  |  |

## 4. Defects and iteration
- [ ] Record failed scenarios and reproduction details.
- [ ] Assign severity, owner and next action.
- [ ] Retest after changes.
- [ ] Document accepted limitations and residual risks.
- [ ] Confirm readiness against agreed acceptance criteria.

## 5. Release readiness
- [ ] Required evaluation scenarios have been completed.
- [ ] Critical defects are resolved or formally accepted.
- [ ] Stakeholders understand known limitations.
- [ ] Documentation and operational ownership are ready.
- [ ] Go/no-go decision is recorded.

> This is an illustrative delivery/evaluation framework, not a representation of proprietary AI model testing or confidential employer documentation.
